# v5.1.3-dojobay.10

The paired-explorer policy lands whole, a deep PSBT and import
hardening sweep rides along, Sparrow BBQr label exports import, and
wrong-network collections grey out everywhere. Tor moves to
0.4.9.14 and BouncyCastle to 1.86. 52 PRs since
v5.1.3-dojobay.9; 34 issues closed.

## Fixed since v5.1.3-dojobay.9

### One explorer policy (#342)

- Every in-app explorer lookup binds to the paired Dojo's published
  explorer when that explorer is the Dojo's own and matches the
  active network (#512): transaction details compass, UTXO details
  (the menu existed but was never inflated), broadcast and sweep
  success sheets, WebView copy-link, and Settings > Explorer.
  Blockstream and Blockchair are gone from the settings list; the
  schemeless Blockstream onion went with them. Vendored Blockstream
  and OXT hosts are gone. Nothing is sent to a third party unless
  the user asks.
- The Privacy row names its one visible action: Analyze externally
  opens am-i.exposed for that transaction, after the advisory, even
  when a paired explorer is bound (#512). The web hash router reads
  `tx`, `addr`, `check`, and `xpub` only; no backend or API
  parameter a deep link can set. The advisory says am-i.exposed is
  a third party whose page fetches blockchain data from the
  mempool.space API, that a direct load lets both see the IP
  address, and that the lookup bypasses the paired explorer. The
  pairing suggestion is dropped from that advisory.
- Only an onion explorer binds as the paired explorer (#518,
  SR-23): a pairing payload - community-list Dojo included - that
  publishes a clearnet URL leaves the lookup unbound, the same way
  clearnet mempool.space already worked. The authority's host
  decides, so the userinfo trick (`x.onion@evil.example`) and a
  path-embedded `.onion` cannot fake an onion. A clearnet Custom URL
  carries the same third-party advisory as the mempool choice; the
  final page URL decides, not the saved template.
- The shortened paired onion shows its tail so it can be verified
  (#513 via #512), a standing explorer check says who runs the
  paired Dojo, and the block explorer re-probes when the Tor SOCKS
  session changes (#517): a probe from a dead Tor session no longer
  stands, an in-flight check against a stale port is cancelled and
  rerun, and the proxy is cleared on Tor stop and start.
- The explorer WebView never loads direct when Tor is required
  (#472 via #481): the Tor-off arm of `onCreate` and the
  proxy-unsupported Continue arm both route through the same
  Tor-required decision as the rest. When Tor stops before any page
  has loaded, the spinner ends in an explanation instead of
  spinning forever (#502).

### PSBT verification (#469, #477)

- Native SegWit PSBT inputs no longer trust Dojo amounts (#469 via
  #478): the previous transaction is fetched per input, and its
  txid, index, and amount are verified before `addInput`. Nested
  SegWit (49) and taproot (44) legs record the fetched prev tx's
  amount, not the Dojo-reported one; a fetch failure fails closed
  instead of silently skipping the map entry or passing empty hex.
- Compose verifies the prev tx's script as well (#477 via #493): a
  lying Dojo can no longer serve a genuine prev tx paying a script
  this wallet does not control. The #226-value guard holds.
- Sweep sign+broadcast is gated on UTXO chain verification (#477
  via #498): the sweep button no longer signs straight from a
  claimed utxo list.
- The unsigned transaction inside a PSBT is parsed with bounded
  reads (#503 via #507): input, output, witness, and script counts
  size their lists only after the bytes are checked to be there,
  and a malformed script hex fails closed. The
  previous-transaction response is capped on the socket
  (`OutOfMemoryError` is not an `Exception`), byte one past the
  cap is not retained, and the refusal text stays one generic
  sentence - no user-facing text or log carries the input txid
  (#508). The unused getTxHex timeout builder is dropped instead
  of replacing the Tor call ceiling.
- Untrusted PSBT, transaction, label, and paste reads are bounded
  (#501): a 16-bit PSBT field length no longer reads as negative,
  a 32-bit length is compared before the array is built, gzip
  inflation of a PSBT string has a stop, and public-key,
  descriptor, pairing, private-key, and password pastes carry
  length caps.
- PSBT globals end on the BIP-174 separator (#462 via #466), not a
  hard-coded count; a payload that ends mid-map or continues past
  the last map is rejected. Dust outputs are rejected while
  composing (#463 via #467), the same 546-sat threshold as change
  selection, with the dust error attached as the cause of
  "Unable to create tx". Broadcast says PSBT (#464 via #474)
  instead of "Incompatible format", and the two Send amount debug
  prints are gone.

### Import limits and honesty (#471, #475)

- Backup, transaction, and paste imports enforce real size limits
  (#471 via #479): `available()` is no longer trusted to bound
  `readText()`, pasted backups are capped before JSON parsing, and
  the reads throw through the existing error reporting instead of
  `OutOfMemoryError`.
- An imported backup lands its tx history on the first sync round
  (#475 via #486): the auto round routes through
  `fetchFromServer`, so the newest tx page the Dojo already sent
  with `/wallet` is no longer discarded. Sync-complete is not
  declared over unread data, and a missing collection id is
  counted as a failure, not silently dropped.
- A second import merges instead of duplicating (#497): a
  collection with the same name and the same public-key set is not
  added again; keys the device already has keep their labels and
  settings, keys it does not have are appended, and an exact set
  match wins over a partial one.
- Collection edit Save persists and closes on the first tap
  (#495): the keyboard-dismissing resize no longer cancels the
  click, Save does not reset the screen on its way out, and a
  name typed into the live collection on every keystroke cannot
  leak into the next sync.

### Sync round honesty (#489, #487, #499)

- A failed sync round no longer re-arms on its own writes (#489
  via #510): the round's own balance and `lastRefreshed` writes,
  arriving after the failure cleared `lastRoundSignature`, no
  longer let the same list straight back in. The trailing re-run
  fires only on a real list change (#489 via #490).
- Off-network collections are skipped in a sync round (#487 via
  #509): the round attempts only what the #429 row state leaves
  ungreyed, in both network directions. Skipped collections are
  not fetched, not gated, and left out of both numbers in
  "N of M". A round with nothing on the active network succeeds.
- Partial collection failures are reported (#499 via #506): the
  terminal branch no longer needs every collection to fail
  before it counts some failures; the partial-Failed state clears
  `lastRoundSignature` so a real external arm can retry, and
  `lastSynced` is written only on a clean Success. The
  deterministically-Indeterminate round (#491) closed with this
  family.

### Privacy

- A third-party 401 can no longer disclose the Dojo access token
  (#468 via #476): the token authenticator is attached only for
  the configured Dojo host, so an exchange-rate provider's 401 no
  longer triggers a real Dojo login and retries the third-party
  URL with the `at` token. A rejected Dojo login cannot
  recursively invoke the authenticator (#470 via #494):
  `/auth/login` is built without it, one re-auth is shared
  across a burst of 401s, and the login POST omits the stale
  token.
- The add-key flow no longer passes the full PubKeyModel - label,
  balance, indices, fingerprint - as an Intent extra (#484 via
  #492); a process-local single-use handoff carries a random
  token instead. ImportSegWitService does the same for the XPUB
  and account type (#465 via #482).
- Dojo pairing credentials, the pairing QR, and the pairing
  scanner are secured on their own dialog windows while showing
  (#516), so a pairing sheet cannot be screenshotted even with
  Disable Screenshots off. The Dojo credentials sheet and the
  camera scanner follow the setting (#511 via #514): an explicit
  on still secures, a missing key no longer forces the flag, the
  PIN pad secures its host while a pad is up, and the host
  returns to the setting when the last pad leaves.

### Restore, PIN, and Settings

- A restore onto a keyless install offers to set a PIN (#420 via
  #456): the offer says the backup has no PIN on this device,
  accepts through the existing confirm pad, rewrites the
  restored payload files to stay readable, and never alters the
  wrap or the KDF. Older backups carrying a verifier still take
  the verifier pad and are not asked twice; a device that already
  has a PIN keeps it and says the backup PIN was not applied.
- The set-PIN offer sits above the import button, not under it
  (#460 via #461): while the offer or the notice is up, the
  bottom import button is not drawn and floating snackbars are
  dismissed.
- The PIN remove toggle works on the first try (#433 via #439,
  #440 via #441): pad records are closed by name, and the
  asynchronous `popBackStack` drain that could crash with
  `OutOfMemoryError` is gone. The pads are isolated from
  accessibility while showing (#496).
- RestorePinPromptTest awaits the pin-configured effect (#504
  via #505), closing the looper race that flipped CI red on the
  #498 push.

### Pairing and label import

- Sparrow BBQr label exports import (#70 via #453): the scanner
  accumulates Coinkite `B$` frames - repeated indexes, parts out
  of order - runs the same labels JSONL check as the file and UR
  paths, and hands the text to the existing importer. The
  collected/total count shows on the scan sheet; a garbled frame
  is skipped while parts are still missing, a later scan can
  finish the series, and a file type this path cannot treat as
  text says so. Series integrity and inflate are hardened
  (#454), and label scans pause while the BBQr conflict dialog
  is showing (#457). UR and BBQr stay in separate sessions.
- UR part outcomes are counted and QR analysis is faster (#71
  via #451): QRPerf gets `newParts`, `repeatParts`,
  `rejectedParts`, `avgAnalyzeMs`, and frame geometry from the
  first YUV frame (#447). Counters and timings only - no
  payloads, labels, xpubs, or frame bytes.
- Pairing payload failures are told apart (#399 via #448): a
  decrypt that does not open is separate from a payload that
  opens but cannot be read - not JSON, an unrecognised shape,
  the older `wallet` export, a newer Ashigaru version - and
  skipped slots are named. The wallet-import key count cannot
  go negative. Pairing passwords typed with no separator at
  all are accepted (#431 via #443): a left-to-right greedy scan
  over the prefix-free EFF wordlist parses `abacuszoomabdomen`
  as `abacus-zoom-abdomen`, and the suggestion UI keeps working
  mid-word.
- Camera permission is asked on the scan page, not at the
  doors (#432 via #445): the Dojo button, remove-Dojo, and
  first-run setup no longer ask before a path is picked. The
  import success snackbar gets its object and a sentence break
  (#436 via #442). BIP-329 copy names Ashigaru Desktop
  alongside Sparrow (#458 via #459).

### Wrong-network collections (#429)

- Collections that do not match the active network render visibly
  inactive everywhere the adapter paints them - Home rows and the
  collection-select sheet - with the header total summing only the
  active network (#430). A network switch repaints live; no
  pull-to-refresh. Grey is informative, not a gate: rows stay
  clickable for view-only access.
- The badge copy fits the measured two-line budget (#434), keeps
  its semantic break mid-phrase (#437), and the dim moves to
  content views so item animators cannot whiten it (#435, #438) -
  all found on the device leg of the staging build.

## Worth a specific check

1. Pair a Dojo whose payload publishes a clearnet explorer URL: the
   lookup stays unbound and offers mempool.space or Analyze
   externally; nothing loads silently (#518 / SR-23).
2. Pair a Dojo with an onion explorer: lookups bind, the shortened
   onion shows its tail, and no advisory interrupts (#512, #513).
   Restart Tor: the explorer probe re-runs on the new SOCKS
   session (#517).
3. Compose with a lying Dojo: prev-tx txid, index, amount, and
   script are verified per PSBT input and the compose fails closed
   (#469 via #478, #477 via #493); sweep refuses to sign an
   unverified utxo (#498).
4. Import a backup: history lands on the first sync round (#486),
   a second import merges instead of duplicating (#497), and the
   edit Save persists on the first tap (#495).
5. A mixed-network wallet: off-network rows grey out (#430) and
   stay grey across item animations and pull-to-refresh (#435,
   #438); a sync round skips them (#509) and a failed round does
   not re-arm (#510).
6. Restore a keyless install: the set-PIN offer appears above
   Import (#456, #461), and the PIN remove toggle works without
   leaving Settings (#439, #441).
7. Scan a Sparrow BBQr label export: parts count up, garbled
   frames skip, and the import lands (#453, #454). Type three
   EFF words with no separators: pairing accepts (#443).
